## 예측의 근거

### 잡힐 것으로 본 항목

CIS 벤치마크와 AWS FSBP 표준에 **명시적인 규칙이 존재하는 설정값**들이다.
"퍼블릭 액세스 차단이 켜져 있는가", "암호화가 적용되어 있는가" 처럼
참·거짓으로 판정 가능한 상태이므로 자동 점검의 대상이 된다.

### 못 잡을 것으로 본 항목

**6번(평문 비밀번호)** — CSPM 은 클라우드 리소스의 *설정*을 본다.
EC2 인스턴스 안의 파일 내용은 점검 범위 밖이다.
이 영역은 CWPP 나 별도의 시크릿 스캐닝 도구가 담당한다.

**13번(프라이빗 서브넷 부재)** — 네트워크 구조는 설계 의도에 따라 달라지므로
"퍼블릭 서브넷에 DB 가 있다"는 사실 자체를 위반으로 판정하기 어렵다.
단, 3번(RDS 퍼블릭 액세스)을 통해 간접적으로 드러날 가능성은 있다.

### 부분적으로 잡힐 것으로 본 항목

**5번(과도한 IAM 권한)** — Access Analyzer 는 외부 접근과 미사용 권한을 분석하지만,
"S3FullAccess 가 이 워크로드에 과하다"는 판단은 사용 이력이 쌓여야 가능하다.
생성 직후에는 호출 기록이 없어 분석이 어려울 것으로 본다.

**10번(HTTPS 미적용)** — ALB 나 CloudFront 를 쓰지 않고 EC2 에 직접 붙는 구조라,
"리스너가 HTTPS 인가"를 판정할 대상 리소스 자체가 없다.

## 확인된 공격 경로 (Attack Path)

개별 항목보다 **조합**이 위험하다. 실제 사고는 단일 취약점이 아니라
연결된 경로를 통해 발생한다.

```markdown
[경로 A] 애플리케이션 SSRF
  → IMDSv1 호출 (#7)
  → EC2 역할의 임시 자격증명 탈취
  → S3FullAccess 권한 (#5)
  → 계정 내 모든 버킷 접근
```

```markdown
[경로 B] 인터넷에서 직접 DB 접근
  → 3306 포트 전체 개방 (#2)
  → RDS 퍼블릭 액세스 (#3)
  → 저장 암호화 미적용 (#3)
  → 데이터 평문 획득
```

Day 3 의 우선순위 판단에서 이 두 경로를 1순위로 둔다.
