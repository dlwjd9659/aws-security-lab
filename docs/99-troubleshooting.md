## 탐지 서비스를 켰는데 감시 대상이 없었다

### 상황

서울 리전에 EC2, RDS, S3를 만들고 탐지 서비스를 활성화했다.
콘솔에서 하나씩 켠 뒤 CLI로 확인하자 오류가 났다.

```markdown
InvalidAccessException: Account ... is not subscribed to AWS Security Hub CSPM
```

### 원인

콘솔 리전이 us-east-1이었다.

IAM과 Budgets 화면은 글로벌 서비스라 리전 선택이 잠기고 항상 us-east-1로 표시된다.
그 화면에서 검색창을 타고 다른 서비스로 넘어가면 리전이 따라온다.
우측 상단 표시를 매번 확인하지 않으면 알아차리기 어렵다.

전 리전을 훑어보니 IAM Access Analyzer가 us-east-1에만 있었다.
서울에는 없었다. **감시 도구는 켜져 있는데 감시할 리소스가 없고,
리소스가 있는 리전에는 감시 도구가 없는 상태였다.**

```bash
for r in $(aws ec2 describe-regions --query 'Regions[].RegionName' --output text); do
  aws accessanalyzer list-analyzers --region $r --query 'analyzers[0].name' --output text
done
```

### 조치

us-east-1의 분석기를 삭제하고 서울에 다시 만들었다.
콘솔 설정에서 기본 리전도 서울로 고정했다.

### 남은 생각

처음엔 비용 문제라고 생각했다. 안 쓰는 리전에서 과금이 생기니까.
그런데 더 큰 문제는 탐지 공백이었다.

과금은 청구서에 찍히니 언젠가 발견된다.
탐지 공백은 아무 일도 일어나지 않는다. 대시보드는 초록색이고,
위반 건수는 0이다. 실제로 안전해서가 아니라 **아무것도 보고 있지 않아서** 0이다.

보안 도구가 "문제 없음"이라고 할 때 두 가지를 구분해야 한다.
검사했는데 괜찮은 것인지, 검사 대상에 들어가지 않은 것인지.

실무에서는 SCP로 허용 리전을 제한해 이 문제를 막는다.
이 프로젝트는 단일 계정이라 적용하지 못했지만,
왜 그 통제가 기본으로 들어가는지는 알게 됐다.

리전별 현황을 빠르게 보려면 Cost Explorer를 리전 기준으로 그룹화하는 게 낫다.
금액이 찍히는 리전이 뭔가 돌고 있는 리전이다.
설정을 하나씩 뒤지는 것보다 확실하다.
