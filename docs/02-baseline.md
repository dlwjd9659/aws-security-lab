# 기준선 측정 (Before)

`terraform/insecure/` 적용 후 탐지 서비스를 24시간 가동한 상태의 측정값이다.
Day 3 에서 `secure/` 적용 후 같은 항목을 다시 측정해 비교한다.

- 측정일: 2026-10-29
- 리전: ap-northeast-2
- 측정 대상: EC2 1, RDS 1, S3 2, VPC 1 (+ 기본 VPC)

### 어느 숫자를 Before 기준으로 쓸 것인가

**전체 81% 는 쓰지 않는다.** FSBP 의 290 개 통과 항목이 평균을 끌어올려,
29% 와 86% 라는 두 개의 다른 상태가 하나의 숫자에 묻힌다.

**CIS 29% 와 FSBP 86% 를 따로 기록한다.** 둘은 측정하는 대상이 다르다.

## 결정적 발견: CIS 실패의 대부분은 내 인프라와 무관하다

CIS 실패 29 개 컨트롤을 원인별로 분류한 결과다.

| 분류 | 컨트롤 수 | 내용 |
| --- | --- | --- |
| 심은 취약점이 직접 원인 | **2** | EC2.13, CloudTrail.4 |
| 내가 만든 VPC 의 부수 효과 | 2 | EC2.2, EC2.6 |
| 계정 생성 시점의 기본 상태 | **25** | IAM 정책 9, CloudWatch 알람 14, CloudTrail 2 |

### 계정 기본 상태 25 건의 내역

| 그룹 | 건수 | 예시 |
| --- | --- | --- |
| CloudWatch 메트릭 필터·알람 | 14 | 루트 사용자 사용, 비인가 API 호출, 콘솔 로그인 실패 알람 |
| IAM 비밀번호 정책 | 7 | 대문자·소문자·기호·숫자 요구, 길이 14 자, 재사용 금지, 90 일 만료 |
| CloudTrail 부가 설정 | 2 | 저장 암호화, CloudWatch Logs 연동 |
| 기타 IAM | 2 | 지원 역할 미생성(IAM.18), 사용자에 정책 직접 연결(IAM.2) |

**IAM.2 는 Phase 0 에서 내가 만든 것이다.** `lab-admin` 사용자에
`AdministratorAccess` 를 직접 연결했는데, CIS 는 그룹을 통해 부여하라고 본다.
의도치 않게 심은 14 번째 취약점인 셈이다.

CloudWatch 알람 14 건은 Low 19 건의 대부분을 차지한다. 전부 "로그 메트릭 필터와
경보가 존재하는가" 를 묻는 항목이고, 신규 계정이면 예외 없이 실패한다.

## 심은 취약점은 FSBP 가 잡는다

CIS v1.2.0 실패 목록에 #1, #3, #4, #7, #11, #12 가 하나도 없다.
CIS v1.2.0 은 2018 년 기준이라 IAM, 로깅, 모니터링 중심이고 리소스 설정
점검이 얇다. 보안 그룹도 22 번과 3389 번 포트만 본다.

같은 항목들이 FSBP 에서는 전부 잡혔다.

| 취약점 | FSBP 컨트롤 | 심각도 |
| --- | --- | --- |
| #1 S3 퍼블릭 | S3.2, S3.8, S3.1 | 매우 중요 / 높음 / 보통 |
| #2 포트 개방 (3306 포함) | EC2.19, EC2.18 | 매우 중요 / 높음 |
| #3 RDS 퍼블릭 + 비암호화 | RDS.2, RDS.3 | 매우 중요 / 보통 |
| #4 EBS 암호화 | EC2.3, EC2.7 | 보통 |
| #7 IMDSv1 | EC2.8 | 높음 |
| #11 RDS 백업 0 일 | RDS.11 | 보통 |
| #13 퍼블릭 서브넷의 DB | RDS.46, EC2.9, EC2.15 | 높음 / 높음 / 보통 |

**13 개 중 10 개를 FSBP 가 잡았고, CIS 는 1.5 개를 잡았다.**

### FSBP 48 건의 구성

| 분류 | 컨트롤 수 | 내용 |
| --- | --- | --- |
| 심은 취약점이 직접 원인 | 약 19 | 위 표 + EC2.2, EC2.6, S3.9, CloudTrail.4 |
| 탐지 도구 미활성 | 8 | Inspector 3, GuardDuty Runtime 4, Macie 1 |
| VPC 엔드포인트 미설정 | 7 | EC2.10, EC2.55~60 |
| 계정 기본 상태·운영 모범 사례 | 약 14 | RDS 운영 옵션, Account.1, IAM.7 등 |

CIS 에서는 "계정 기본 상태" 가 25/29 였으나, FSBP 에서는
**심은 취약점이 가장 큰 덩어리**다. 두 표준의 성격 차이가 그대로 드러난다.

## 다른 도구의 측정값

| 도구 | 값 | 비고 |
| --- | --- | --- |
| GuardDuty | (기재) | 샘플 결과 포함 여부 반드시 구분 |
| Inspector | (기재) | `python:3.8-slim` 관련 CVE |
| IAM Access Analyzer | (기재) | 외부 접근 가능 리소스 |

GuardDuty 요약 화면의 위협 유형(`Trojan:Runtime-DropPoint!DNS`,
`Backdoor:EC2-C&CActivity` 등)은 **샘플 결과 생성 기능으로 만든 데이터**다.
실제 공격이 아니므로 기록할 때 반드시 구분한다.

실제 스캔 흔적을 보려면 GuardDuty 결과 목록에서 샘플 필터를 제외하고 확인한다.
